# 从历史课修订教法，用 StudentBench 原导师策略教下一名学生

我们希望导师学会判断，一名学生在帮助下答对后，哪一步仍值得让下一名学生独立做一次。历史课负责产生可以撤回的教案修改。最终给新学生回话的仍是 StudentBench 发布的 GRE 数学导师策略。两种教案共用同一个 `gpt-6-luna`、同一段课堂历史和同一套生成参数。两名留出学生中，原教案有 0 条回复做到预先指定的教学动作，接入 skill 后有 1 条。两条新回复都没有给真人施教。[预先固定的话轮和判断标准](native_targets.json) · [三种导师回复全文](native_runs/comparison.json)

## 最终推理怎样对照

从发布的小模型条件 `ai_arm_gpt-5.4-mini-none` 按编号取前两场，与建库的 Gemini 组分开。原数据中的导师是 GPT-5.4 mini。离线配对时读入作者发布的 `gre.quant.tutor.lean.v3`，填入原教案的概念名和 `why_it_matters`。实验组仅在后一个字段附上从旧课检索到的一步。两组的前测画像、该概念当时已经显示的题目、提交与对话完全相同，均使用 low 推理强度、1,100 个最大输出 token。作者公开了提示模板和事件日志，逐请求的角色消息封装由本项目重建。[官方提示模板](https://huggingface.co/datasets/handshake-ai-research/studentbench/blob/304c8d63c726e72b60510bba3a44454fc0726721/5_prompts/gre.quant.tutor.lean.v3.txt) · [提示发布说明](https://huggingface.co/datasets/handshake-ai-research/studentbench/blob/304c8d63c726e72b60510bba3a44454fc0726721/5_prompts/README.md) · [请求指纹](native_runs/design_lock.json)

**原研究的学习指标。** 原导师条件下，0104 的正式前后测为 20→18，0108 为 22→25，各满分 27。研究论文合并多个 AI 导师并校正前测后，数学组相对无导师对照的学习增益为 6.86 个百分点，95% 区间为 4.02 至 9.69。这个数属于原研究的组间比较。本项目两组 Luna 回复对应的后测均为空。[两名学生的真实成绩与重放输出](native_runs/comparison.json) · [StudentBench 表 B.2](https://arxiv.org/html/2609.28470v1)

## 建库时，学生的理由改变了什么

排除前 10 个开发场次后，按序核对 46 个新场次，纳入 12 个。每人有一堂最终答对的原课，同一场中另有一道新题，学生在该题首次反馈前给出了答案和理由。其余 34 场的筛除原因逐人保留。两种输入共用原课、选项、学生答案、题目正解与模型，只在其中一组显示学生自己写的首答理由。研究者依据记录编写了候选动作和临时参考选择，并在调用前锁定。这个环节检验从候选中作出改课判断的能力。[筛查记录](screening.csv) · [实验约定](protocol.zh-CN.md) · [逐例参考与依据](cases.json)

| 12 例中的比较 | 只看答案 | 加上学生理由 |
| --- | ---: | ---: |
| 与项目事先写下的参考动作一致 | 3/12 | 6/12 |
| 去掉事先标记的三个模糊案例 | 1/9 | 3/9 |

4 例由不一致变为一致，1 例反向变化，其余 7 例动作相同。双侧精确配对检验得到 p = 0.375。0402 把“指数更大”当作正底数幂更大的理由，模型因而选了让学生比较小于 1 和大于 1 的正底数。反例 0608 已独立说明两种不同结果，加入理由后模型却又要求取证。最终有 8 例建议先取证、3 例建议定向修改、1 例保留。候选教法和标签有研究者参与，教师独立评阅仍为空。[模型选择与逐例结果](runs/text/summary.json) · [独立评阅包](runs/text/blind_review.json)

12 场均能定位原 Gemini 导师在学生作答后的真实回复。再用原教案列出的前测题标识，经过题库的配对号关联同一学生另一套正式后测，得到 21 条记录，18 条答对。这些题与教案标注的概念有关，一个概念可覆盖多个题型。这 18 条正确只描述当年的课堂经历，无法判定 12 项候选改法各会带来多少收益。[原回复、配对题号和作答](dataset_baselines.json)

## 用围栏数据集自己的方法核对

按公开 R 脚本，以 400 人的组内合并残差标准差标准化，在 99 名苏格拉底辅导学生中回归三道对应变式的合计成绩。每多纠正一道练习的系数为 0.405，每多一道初答正确的系数为 0.697，重现论文表 S4 的 0.41 和 0.70。再留出形成想法时读过的 p019，在其余 98 人中逐人留一，所有模型使用相同学生和 0–9 分目标。[原研究第 4.6 节及表 S4](https://arxiv.org/pdf/2611.20061) · [作者分析脚本](https://github.com/the-oak-lab/scaffolded-error-correction/blob/98c52a668fc6ba76fa330eb9539ab893616111ba/socratic_analysis.R#L385-L421)

| 同样的 98 人，普通最小二乘 | 留一平均绝对误差，越低越好 |
| --- | ---: |
| 作者原有的纠正题数和初答正确题数 | 2.156 |
| 再加三题的交互次数、单门题是否由错改对 | 2.091 |
| 再加带价围栏题两类初答算式，以及单门题的关键关系是否由学生先说 | 2.087 |

控制帮助量和适用人群后，增加上述过程信息仅再少错 0.004 分。这里估计的是总分预测误差，p019 具体怎样答双门题仍未知。p019 在原题只需扣一次 10 英尺，按实际缺口计数与“一律只扣一处”都能写对。如果他在未获提示的双门新题自行扣去两处并说清原因，应撤回对他增设多门补教的建议。[逐人预测](dataset_baselines.json) · [p019 的原始证据、两种预测和撤回条件](../../cases/p019.zh-CN.md)

## 本地复核

从仓库根目录运行。围栏回归使用 NumPy。前四条数据命令读写固定版本的公开研究数据，末两条读取已经保存的 API 响应。

```sh
python -m pip install -e ".[pilot]"
python scripts/fetch_sec.py
python scripts/screen_reason_trials.py --fetch --limit 46
python scripts/fetch_native_baselines.py
python scripts/run_dataset_baselines.py
python scripts/run_reason_trials.py --summarize-only
python scripts/run_native_tutor.py
```

本轮建库对照有 24 次正式生成。最终推理有 4 次，合计 4,504 个输入 token 和 1,487 个输出 token。最终推理默认复用缓存，只有显式加 `--run` 才会发送缺失请求。公开 StudentBench 数据由 Handshake AI Research 以 CC BY 4.0 发布，两份数据清单均固定到同一发布版本。[建库数据清单](sources.json) · [原导师、教案与正式测验清单](native_sources.json)
